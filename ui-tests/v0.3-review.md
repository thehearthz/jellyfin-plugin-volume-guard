# Volume Guard settings review

This is an extension of the existing embedded Jellyfin settings component. It keeps the host's font, colors, controls, and authentication. No new design direction was drawn. The standalone preview uses mock data for a Bedroom Chromecast session; that data is confined to the browser test and is never shipped as plugin status.

The screen answers: “Is audio processing running, and how should it behave on this device?” Playback status comes first, followed by explicit controls and one Save action. Its product-specific element is the distinction between a confirmed server filter launch and an unconfirmed listening result.

## Checks

- Browser integration checks cover configuration and status routes with reverse-proxy paths, opt-in defaults, dialogue and analysis settings, per-device serialization, duplicate IDs, automatic switching, overnight windows, 204 saves, authentication failures, and retained unsaved edits during status refresh.
- Failed status refresh keeps the last successful snapshot and displays an error. The freshness timestamp remains visible.
- Taste app-screen lint and browser inspection passed with zero failures or warnings at 1440, 768, and 390 pixels. Inspection caught standalone mobile text autosizing; a viewport declaration fixed it. Preview button contrast was also corrected without overriding the host's shipping styles.
- All final desktop, tablet, and phone fold/page screenshots were opened and reviewed. Controls stack on the phone and the page has no horizontal overflow.

## Visual critique

1. Playback status leads with the device, launched mode, reason, dialogue, and analysis. No acoustic measurements are invented.
2. Sections share equal outer margins. Two-column controls use equal tracks and one gutter, collapsing to one track on a phone. No panel stretches to fill unused space.
3. Host colors remain neutral; the one Save action carries the preview accent. No decorative charts, counters, or additional palette were introduced.
4. Status and analysis text come from the same server snapshot; settings remain a separate unsaved draft. No computed totals are displayed.
5. Missing status values say “Unavailable”; an absent analysis summary is stated directly. Empty device overrides explain global inheritance.
6. There are no charts or legends. Descriptions sit beside the controls they explain.
7. Phone controls retain labels and touch targets. The long settings form follows the existing Jellyfin plugin pattern rather than introducing separate navigation.

Physical Chromecast, real Jellyfin host styling, screen-reader output, and client restart behavior require device testing; the preview checks do not certify those.
